# 开发与测试文档

本文是面向开发者的技术文档：架构、测试、数值模拟、环境变量与 v1 已知取舍。
玩家向的玩法说明见 [README](../README.md)，完整规则见 [somegame.md](../somegame.md)。

## 架构

```
src/SomeGame.Core     确定性仿真核心（无 UI 依赖，纯数据驱动，可回放）
src/SomeGame.Server   权威服务器：房间管理 + WebSocket 网关 + 静态 UI
tools/SomeGame.Balance 卡池数值模拟工具
tests/...             xUnit 单元/仿真测试
```

- **权威服务器**：所有隐藏信息（身份/手牌/受保护 NPC/地图卡池/伪装等）只在服务端，按客户端“应知信息”过滤下发，防作弊与防信息泄露由服务端边界保证。
- **数据驱动**：角色/卡牌/配比/地图/计时/敌对关系全部来自 `SomeGame.Core/Data/default.json`（内嵌资源），新增卡牌与身份无需改引擎。
- **生产-消费流水线**：玩家指令、机器人决策、NPC 行动、超时事件统一汇入单线程确定性仲裁，输出事件日志（可回放）。
- **房间隔离**：每个房间一个独立 `Game` 实例，互不阻塞，支持多局并发。
- **并发模型**：服务端对所有**对局写操作**（客户端指令、机器人/超时自动决策、断线接管）统一加一把全局锁串行化，避免对同一 `Game` 的并发写入与脏状态。

## 运行

```bash
dotnet run --project src/SomeGame.Server
# 浏览器打开 http://localhost:5123
```

### 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `SOMEGAME_PORT` | `5123` | 监听端口 |
| `SOMEGAME_DECISION_MS` | `60000` | 真人决策超时（毫秒），测试可设小值 |

## 测试

```bash
dotnet test
```

覆盖：配置/卡池、确定性回放、四角色胜负结算（E1-E4）、身份查验敌对关系、人类移动/查验流程、全机器人完整对局收敛，以及卡池配比与 1v1 战斗强度校验。另有安全/健壮性用例：伪装不泄露真实敌对性、撤离点坐标按需下发、无效出牌不扣资源、瞄准/隐匿攻击后消耗、标注/掩护每回合上限、万能胶陷阱触发（含医疗包/探查/布置者豁免）、查验用错卡保留机会。

## 数值模拟（卡池校验）

```bash
dotnet run --project tools/SomeGame.Balance -- 3000 12   # 参数：1v1 模拟次数、8人局数
```

自动生成 [`docs/balance-report.md`](docs/balance-report.md)，包含：
1. 卡池构成（攻防类占比目标 55-60%，特殊类每型 2-4 张）；
2. 五种 1v1 场景的蒙特卡洛结果（平均攻防对抗目标 ≈3，含杀手补给/弹药包等临时卡）；
3. 8 人双案局机器人压力验证（收敛率、平均回合、结局分布）；
4. 对局过程指标（杀手/小偷/保镖首次接近贵宾的回合、首次战斗、贵宾暴露、人均自由行动与查验密度、行动构成分布）——用于把握"找目标耗时"与"玩家每回合是否有事做"。

> 结论：裸手牌枪战约 1.6 次对抗偏低，但计入杀手每回合补给/弹药包等临时卡后为 3.6-5.6 次，符合“算上临时卡平均三次对抗”的预期；单场战斗多为消耗战，胜负主要靠跨回合磨损与撤离线结算。

## v1 范围与已知取舍（相对设计文档的简化）

为在首期交付可玩闭环，以下部分做了收敛实现（设计语义以 `somegame.md` §9/§10 为准，代码行为以源码为准）：

- **自由行动阶段**：实现为按座位顺序的“微回合”，而非文档设想的完全并行；每人仍拥有每回合 3 行动点，先到先走。
- **玩家间通讯**：无聊天，仅游戏内“交谈”动作与行动记录。
- **NPC 行为**：普通 NPC 随机走动/交谈；受保护 NPC 仅在**第 5 回合起（撤离点对贵宾开放后）**且满足"被保镖催促"或"身份已暴露"时才向撤离点移动（默认 1 格/回合，暴露且被催促为 2 格），烟雾/燃烧会让其先行避险。NPC“可疑/指认”记忆系统简化，暂不实现；NPC 也不主动交互物品，故不触发万能胶陷阱（玩家开箱/拾取医疗包/探查时触发）。
- **卡牌**：21 种类型全量定义；效果已实现核心子集（隐身/枪械/刀械/闪避/防暴盾/兴奋剂/治疗/能量/弹药/管制刀具/伪装/模仿/追踪/无人机/窃听器/染色/烟雾/燃烧瓶/万能胶/瞄准/连射）。策略细节以代码为准，数值平衡建议按文档 §9.1 先跑模拟再冻结。
- **追查等身份对抗**：追踪探查可揭穿伪装/模仿；伪装会随机替代同格他人身份。
- **胜负结算**：完全按 E1-E4 事件触发式 + 全盘盘点实现；E5 回合上限兜底。
- **时限**：设计文档 §12 的自由/查验/战斗分阶段时限（90/15/10s）在 v1 统一为单一决策时限 `SOMEGAME_DECISION_MS`（默认 60s），未细分。
- **陷阱**：万能胶可布置于任意可交互物品；触发点为开箱、拾取医疗包、高价值探查，且布置者本人不触发。烟雾弹/燃烧瓶"可作陷阱"的形态尚未实现。

## 已知平衡观察（待后续调优）

8 人机器人局中**保镖阵营明显占优**（贵宾多在撤离线之前安全抵达），疯子清场与杀手线达成率低——这是下一轮平衡的重点方向。
